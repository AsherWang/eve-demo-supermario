# 顶砖道具与城堡旗子修复记录（2026-10-23）

## 顶砖弹起蘑菇

原问题：`hitBlock` 只处理敌人，没有让蘑菇响应被顶起的砖块。

本地原版反汇编的依据：

- `PowerUpObjHandler`：蘑菇和 1UP 进入 `EnemyToBGCollisionDet`；花跳过，星星走另一条逻辑。
- `ChkUnderEnemy` / `BlockBuffer_*_Adder`：检查 ROM 坐标 `(X + $08, Y + $18)` 所在的格子。
- `HandleEToBGCollision`：碰到临时被顶方块 `$23` 后消费该标记，不能反复触发。
- `SetStun`：Y 上移 2 像素，纵向速度写入 `$fd`（-3 像素/帧）。
- `PlayerEnemyDiff` / `EnemyBGCXSpdData`：按与马里奥的相对位置选择 `$10/$f0`
  水平速度（4.4 定点数，即 ±1 像素/帧），并非无条件反向。

实现保留游戏现有的方块弹动窗口，在蘑菇移动后检查底部中心采样点；每次弹动只消费一次。
正在出砖、已拾取的道具不触发，花和星星不套用蘑菇规则。碎砖也检查当时位于其上的蘑菇。

启动自测覆盖：提前顶前方砖块、中心尚未进入时不触发、进入后向上/反向、落地继续走、
马里奥在另一侧时不盲目反向、1UP、花、星星、正在出砖以及已拾取道具。

精度边界：此处移植了采样点、触发条件和初始速度规则；之后仍使用现有宿主浮点重力和碰撞，
不是完整移植 `MoveNormalEnemy` / `ImposeGravity` 的定点状态。现有实现只有一个弹动方块槽，
也不是原版全部方块槽和背景缓冲区的完整模拟。尚需新增这段交互的 ROM 输入回放，验证完整轨迹。

## 城堡旗子遮挡

`DrawStarFlag` 写入 OAM 属性 `$22`：调色板 2，并设置背景优先位，旗子应在不透明城墙后面。
原先 `drawCastle` 最后画旗子，导致升起途中覆盖城墙。现在先画旗子，再画城堡；透明垛口仍可透出。

保留 `RaiseFlagSetoffFWorks` 从 `$90` 上升到 `$71` 的坐标规则，绘制时补上 OAM Y 到可见像素
的 +1 扫描线关系。没有通过随意挪动终点来掩盖层级问题。

自测检查实际绘图调用顺序及最终 Y=114；另已检查真实游戏渲染的隐藏/升起两张诊断截图。

## 本轮回归

`first-powerup-mushroom`、`world-1-1-high-flag` 的画面、状态、事件、APU 写入和测试侧 PCM 对照通过。
这证明已有轨迹没有回退，不等于新增的蘑菇顶砖交互已经逐帧通过 ROM 对照。

前一轮金币修复也包含在当前工作区：绘制使用来源方块相对位移，避免高层金币及“200”分数
沿用低层方块的绝对屏幕坐标；相应高度差、完整生命周期及重叠金币自测保留。

## 启动器与控制台窗口

EVEngine v0.6.0 的 `eve.exe` 使用 Console 子系统，直接启动必然创建控制台。发布包因此
新增 GUI 子系统 `SuperMario.exe` 启动器，以 `CREATE_NO_WINDOW` 启动 `runtime/eve.exe`，
并将 stdout/stderr 写入 `game.log`。引擎宿主和插件保持 x64，未修改引擎本体。
