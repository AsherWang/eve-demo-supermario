# 项目整体 Roadmap

更新日期：2026-10-24。本文以当前源码和本地对照报告为基线；阶段按依赖顺序推进，不承诺日历期限。

## 目标与实现边界

在 EVEngine 中独立实现《超级马里奥兄弟》的关卡和玩法，以原版数据与确定性输入回放验证行为。ROM 和 Mesen 仅用于本地离线提取及参考检测，不进入交互运行时或发布包。

近期目标是完成 World 1-1 / 1-2 的稳定交付和可重复验收，再建立可扩展的关卡组织方式。后续关卡逐关推进，完整游戏属于长期方向，尚无交付日期。可玩、启动逻辑检查通过、固定回放通过和整关严格对齐是不同的完成标准。

## 当前基线

| 方向 | 已有成果 | 尚存边界 |
| --- | --- | --- |
| 1-1 | 地图、敌人、强化、地下房、生命系统、旗杆及结算；七组既有回放共 4260 帧通过 | 延长城堡结算诊断用例失败，极端碰撞和其他未覆盖路线仍需验证 |
| 1-2 | 208 列主图、17 列金币房、入口出口、食人花、升降平台、屋顶和 Warp Zone 选择 | 两组共 420 帧的状态、事件、APU、检测侧 PCM 通过；14 张抽样画面中 3 张不同，整组未通过 |
| 音频 | 原版离线 PCM 素材、独立 Windows 播放插件、实际游戏 PCM 捕获验证工具 | 运行时尚未完整复现 APU 声道抢占及非线性混音；检测侧严格 PCM 依赖参考周期载体 |
| 工程 | Windows 工具安装、原生编译、打包、确定性回放及 HTML/JSON 报告 | 完整 ROM 对照仍在本地执行；跨机器验证尚未完成 |
| 架构 | 玩家状态、ROM 数据、地图构建、模拟及渲染已有分工 | 地图运行状态和流程集中于 game，存在 1-1 / 1-2 专用分支 |

默认套件只包含七组既有用例。1-2 和延长城堡诊断需要显式指定；报告首页会被最近一次套件运行覆盖，不能单凭首页判断所有基线结果。上述数字是固定用例覆盖情况，不代表任意路线均已严格对齐。

## M1：收敛现有关卡差异（当前优先）

- [ ] 修复 1-1 延长城堡诊断从第 1287 帧开始的位置、结算状态及声音时序差异，同时检查产物契约失败原因。
- [ ] 修复 1-2 开场第 0、1 帧及行走第 17 帧的显示差异，追踪 OAM 显示延迟和敌人下落显示。
- [ ] 增加实际触发礼炮的固定输入路线；现有 castle-fireworks 命名用例的时间尾数不满足条件，不能作为礼炮覆盖证据。
- [ ] 同步过时文档，消除“仅实现 1-1”等描述与当前实现的冲突。

验收：七组既有基线继续通过；两组 1-2 和延长城堡诊断全部门禁通过；新增礼炮路线对照通过。保留零容差和失败帧，不通过排除样本消除差异。

## M2：补齐 1-2 整关验收

- [ ] 建立入口自动行走、下管、地下主线和地面出口至结算的完整回放。
- [ ] 覆盖金币房往返和地图修改状态保留。
- [ ] 覆盖升降平台乘坐、离开平台、食人花伤害及管口交互。
- [ ] 覆盖屋顶路线、Warp Zone 三个选项以及当前目的地提示行为。
- [ ] 扩充死亡重生、强化、镜头边界和敌人激活的回归。
- [ ] 核对藤蔓砖等特殊对象的实际奖励与区域连接；当前 TILE_BRICK_VINE 命中分支仍生成蘑菇或火花，需要实现或明确限制。

验收：新增路线具备原版参考及状态、事件、画面和声音报告；明确 Warp Zone 后续世界未实现的边界。稳定通过后，将对应路线纳入常规回归。

## M3：整理关卡架构

在 M1 / M2 提供行为保护后，分步迁移，避免同时改变规则和数据组织。

- [ ] 提取 Player 状态创建与玩家行为，减少与关卡编号的直接耦合。
- [ ] 定义 LevelData：关卡标识、尺寸、地图来源、实体出生点、入口出口、音乐及场景配置。
- [ ] 定义 LevelState：可变图块、实体、已使用方块、镜头及区域保存状态。
- [ ] 建立统一加载和区域切换入口，迁移 1-1 / 1-2 专用构建流程。
- [ ] 将升降平台、食人花、管道、旗杆等规则与具体关卡布置分离。

验收：两关通过统一入口加载，重构前后既有回放保持一致；增加复用现有机制的关卡布置无需修改玩家运动逻辑。

## M4：完善声音与发布保障

- [ ] 评估并分步将独立 APU 写入模型接入运行时，先覆盖已有声音事件和声道抢占。
- [ ] 为独立运行时明确时序来源，再验证非线性混音与 PCM；参考周期载体通过不能代替运行时实现。
- [ ] 增加移动、拾取、受伤、管道和结算场景的实际游戏 PCM 验证。
- [ ] 为低时间警告及地上、地下、星星加速音乐补充触发、恢复和切区回归。
- [ ] 在另一台干净 Windows 环境验证安装、构建、打包和启动。
- [ ] 发布前保存源码提交、工具版本、回归用例清单和结果，检查包内无 ROM、模拟器和测试存档。

验收：发布对应明确提交和验证记录；运行时音频的实测范围与剩余近似在发布说明中可查。

## M5：逐关扩展（长期）

- [ ] 先评估 1-3 的平台机制和 1-4 的城堡机制，按地图数据、玩法实现、参考回放、发布验收的顺序推进。
- [ ] 完成 World 1 的关卡衔接，再规划其他世界及 Warp Zone 的真实目标关卡。
- [ ] 按新关卡需求扩充敌人、机关和场景类型，持续保留已有关卡回归。
- [ ] 根据实际复刻目标决定是否实现 PPU 精灵限制、硬件闪烁及扫描线时序等高成本细节。

验收：每个新关卡分别记录可玩范围、固定用例覆盖和已知差异，不用总体完成百分比替代证据。
